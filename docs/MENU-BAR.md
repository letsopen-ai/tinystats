# Menu bar styles

Select **Menu Bar** in the bottom **Settings** sidebar group to arrange readouts and choose each one's **Style** and **Font**. Labels, numbers and graphical fills adapt to the native menu bar appearance. The main content moves into a persistent resizable window, which survives focus loss and monitoring-tab changes. Its minimum content size is 884×660; switching tabs preserves the chosen window size. Settings forms stay at most 740 points wide and the preview retains actual menu-bar sizing. Changes apply immediately. Click a status item for detail pages; changing its style does not create a separate collector.

The compact icon-only **Layout** control chooses **Separate** (a native item per enabled module) or **One** (all enabled modules in one native item). Tooltips and accessibility identify each choice. Layout changes only `separateItems`, preserving every module's style, font size and order. The preview sits to the left of the Layout control, title and short help in one compact row (74pt maximum including row insets). The native control is at most 28pt high. The customization platter shows **In menu bar** in actual left-to-right order and an **Available** palette. The style editor starts expanded. Click or focus a chip in either tray to select its module, then choose a picture tile. Its header contains the module icon/name and native font-size popup. Sensors adds its sensor popup, Power adds **Battery formats…**, and Time adds **Clock formats…** before the font-size popup when space permits; otherwise the tool uses a compact borderless row above the tiles. **Hide styles** collapses the editor; **Customize styles…**, a completed chip click or VoiceOver press reveals it again. Focus and dragging preserve a chosen collapse.

## Switching an open view

Status-item dropdowns use a 344×640-point popover material with neutral Control Center platters, large label-colour values and accent graphics. Module content scrolls when needed. The 16pt TinyStats paper-tile logo (Open [module] in TinyStats), History…, All readings / Summary (Calendar… for Time), and Pause / Resume share a compact 34-point icon bar at the foot, where applicable. Navigation icons align leading; Pause/Resume sits trailing, below a hairline separator. Each 28-point button has a state-aware tooltip and accessibility label, a subtle rounded hover/pressed highlight and a visible native keyboard focus ring. Tab/Shift-Tab navigate and Space/Return activate; list/grid and pause/play icons reflect the available next action. Reclaimed height goes to the scrolling content within the same 344×640 popover. The open action promotes the same controller to the persistent window and preserves the selected module; it does not visit Settings. CPU cores use vertical capsules in verified E/P secondary/primary accents. History plots disclose their observed duration, sample count and numerical scale, including empty/unavailable states; valid zero readings remain data. Battery detail tiles use two columns in the narrow dropdown. Memory composition uses a segmented accent bar with distinct neutral compressed/available fills. Paired traces use solid/dashed lines as well as named legends. The footer is icon bar only; privacy/cadence/sample cost and paused state are available in All readings → About this sample and Pause/Resume tooltip/VoiceOver help (including Overview). Scrolling content has a 16-point bottom fade/inset above the icon bar, without caption space or a separate clear buffer; All readings retains a 12-point platter gutter for trailing values. Sensor search, calendar date selection and explicit Weather controls remain native controls.

Selecting a different readout switches the existing popover directly to that page in one click; selecting its current readout closes it. This applies to separate items and to segments within One. While open, the local input monitor routes a left mouse-down before native button tracking and consumes that event once; the presentation stays open during a page switch, avoiding delayed close cleanup. Opening and switching happen on mouse-down; dragging off the item after pressing no longer cancels opening. Right-click and native ⌘-drag keep their AppKit paths. Control-click continues to open the dropdown, as before; use right-click for options. Outside clicks, Escape and app switching dismiss the popover. Text editors and attached sheets handle Escape first; in Sensors search, Escape clears the search while keeping the popover open. Settings opens in the persistent resizable window, which stays open after focus loss. Readouts then select pages in that same window. Dismissal handlers are active only while the popover is open. See the 0.35.5 evidence and physical-input limits.

## Reproduce the supplied stacked layout

1. Enable **Sensors**, **Network**, **Disks**, **CPU** and **Memory**. Disable other readouts for the same five-item arrangement.
2. Set **Menu bar sensor** to **CPU · hottest recognized sensor**. Leave **Use Fahrenheit** off for the Celsius version of the example.
3. Choose **Stacked label + value** for all five readouts. Use **Standard** font; colors are automatic.
4. In Settings, drag chips in **In menu bar** into **Sensors → Network → Disks → CPU → Memory** order. Native **⌘-drag** also works. The preview and customization wells follow observed native positions. Chips wrap into rows so every item stays visible; the live preview scrolls horizontally when needed.

The sensor displays a CPU label over temperature, Network puts upload above download, and the remaining items put SSD/CPU/MEM labels over percentages. Values come from the current readings; matching the arrangement does not imply matching a reference image's sample numbers. Unsupported readings remain unavailable.

## Fourteen style families

“All readouts” below means CPU, GPU, Memory, Disks, Network, Sensors, Power (battery formats) and Time. Percentage/temperature gauges apply to CPU/GPU usage, memory, disk capacity, battery level and temperature sensors. Fans, power, voltage and current have no percentage gauge; Network rates and Time also exclude gauges.

| Style | Availability and behavior |
| --- | --- |
| Label + value | All readouts; one line with the metric label and value |
| Stacked label + value | All readouts; label above value, or upload above download for Network |
| Value only | All readouts; omits the metric label, retaining both Network directions |
| Label only | All readouts; a static metric label, or the local weekday for Time |
| Icon only | All readouts; the module's symbol, with readings still available in details |
| History graph | All except Time; last 40 samples, with two Network series |
| History + value | All except Time; the same graph beside a stacked current readout |
| Vertical gauge | Percentage/temperature readings |
| Labeled vertical gauge | Three vertically stacked label letters beside a colored upright gauge; CPU/GPU/MEM/SSD and other percentage/temperature readings |
| Labeled horizontal gauge | Percentage/temperature readings; fixed small caption above a horizontal bar |
| Pie gauge | Percentage/temperature readings |
| Ring gauge | Percentage/temperature readings |
| Per-core bars | CPU only; the first 32 logical cores, where exposed |
| Battery icon | Power/battery readout only; level body with a separate charging badge, or a plug on a Mac without an internal battery |

Temperature gauges use a fixed 0–120°C scale. Fahrenheit changes temperature text while retaining that thermal scale. Sensor histories retain their measured units; signed current graphs include a zero baseline. Network uses decimal B/KB/MB/GB per second in the menu bar, while details use binary KiB/MiB/GiB per second.

## Font, color and ordering

**Compact**, **Standard** and **Large** apply to Label + value, Stacked label + value, Value only, Label only and History + value. General value fonts are 10/11/13 points. Stacked Network values use 10/10.5/11 points to keep both lines within native menu bar height; small stacked labels and horizontal-gauge captions remain fixed. Other styles disable the Font control rather than suggesting it resizes a graph, icon or gauge.

Menu bar text is near-black without a shadow on light bars and white with the existing subtle dark shadow on dark bars, including stacked labels, rates, missing-value dashes and vertical gauge letters. All graphical families (including symbols, clock dials/calendars, gauges, history and battery graphics) follow `NSColor.controlAccentColor`, resolved in the native status item's appearance. Graphics first apply the shared contrast correction from [Design](DESIGN.md#derived-secondary-accent-2026-10-30). Dark-bar primary graphics retain their existing 18% white lift. Paired Network history uses primary for download and the opaque derived secondary for upload; verified E/P cores use secondary/primary. Gauge outlines retain label colour at 65% opacity. Verified efficiency cores use the opaque derived companion, performance cores use primary, and unclassified cores use a neutral label tint. Legacy stored tint fields still decode but do not override rendering. GPU has no verified E/P topology or individual shader-core utilization adapter.

The preview sits on an appearance-aware neutral wallpaper-like strip. It does not read the desktop image or request access. It uses the same renderer, current readings, native menu bar appearance/height and per-item padding as the actual status items, including pause markers. Both layouts always use compact geometry: 0pt side padding and 1pt internal segment gaps. Separate uses the insets around each item; One also applies the gap between segments. Multiple clock entries use the same internal gap. Settings, Welcome, format previews and style pictures use the same compact geometry. Network direction arrows stay at the leading edge while numeric fields stay fixed-width and right-aligned, including short rates and missing values. macOS controls spacing outside each native item. Font changes update the existing items. Physical menu bar space and wallpaper/translucency remain outside the preview.

**Settings → General → Appearance** chooses System, Light or Dark for TinyStats windows, detail panels and child settings. It does not change macOS appearance. Menu bar colors follow the status item’s effective appearance independently of the window theme and redraw when that appearance changes or the system colours change. No background plate or Backing setting is added. Palette tests check accent resolution, label contrast, companion derivation, dark-bar shadow and stable widths; a full dark-bar PNG byte-identity baseline is not part of this change. TinyStats does not sample wallpaper or screen pixels, request new permissions or make network requests for contrast. One appearance covers the item, so local patches of busy wallpapers can still reduce contrast. The Menu Bar preview follows the actual native menu bar appearance independently from the window theme. No animation loop or extra timer is added.

Separate assigns each native status item its destination module. One shares a native button and routes mouse-down input to the exact physical frames used by the renderer. Icon and value belong to the same segment; gaps and outer padding select the nearest segment edge, with equal-distance ties resolved in renderer order. Mouse-down/up handling reads `NSEvent.mouseLocation` in screen coordinates, independent of a nil, in-process proxy or other-process event window. The handlers run synchronously on the main thread before native tracking/activation; the cursor position describes that handling instant. Events from TinyStats’ own status-button windows additionally cross-check `locationInWindow` converted through that window against the visible button rectangles, using the handling-time cursor if the two disagree. Other windows’ local coordinates are never guessed. Screen rectangles come from `button.window.convertToScreen(button.convert(button.bounds, to: nil))`; negative display origins are preserved. Detached, hidden, nonvisible and off-screen overflow items cannot hit. macOS owns placement around the notch. Routing also requires a nil source window, one of TinyStats’ status-button windows, or the open dropdown window. A click inside the dropdown frame passes through before status hit-testing, including overlaps in full-screen/auto-hide layouts. Unrelated owned windows keep their clicks even when their screen pixels overlap a status item. Routing follows drawn frames in either layout direction without separately reversing module order. Multiple custom clock segments all select Time. Keyboard/VoiceOver activation opens the first configured module unless the current AppKit event is a mouse-down/up with the cursor over the button (and toggles it closed if already shown). Settings customization preserves the same ordered readout list in both layouts; native **⌘-drag** reorders modules in Separate. The preview follows observed Separate positions and scrolls horizontally when needed. Available physical space still limits which items macOS can show. The 0.37.1 owned-window regressions drive the production AppDelegate/PopoverInteraction entry points with own-status-window, nil-window, unrelated-owned-window and dropdown-window events, covering single-event switching/toggle, dropdown pass-through, source eligibility, hidden items and combined-segment content. A click received during close animation is retained and opened by the close callback, without a timer; completed closes still report presentation/probe accounting before guarding teardown of a re-shown presentation. `TINYSTATS_SYSTEM_RENDER_PATH=build/mc-evidence` generates `combined-item-{cpu,memory,network,battery}-{light,dark}.png` and `switch-sequence.txt`; optional glass captures use only owned windows with existing authorization. These fixtures do not prove physical status-item delivery on other hosts; no real menu-bar clicks are scripted.

## Maintainer real-click trace

Quit any existing TinyStats instance first (the app rejects duplicate instances). Start unified-log streaming in one terminal, then launch the built app in another:

```sh
log stream --style compact --level info --predicate 'subsystem == "com.niechen.tinystats" AND category == "MenuBarClick"'
TINYSTATS_CLICK_TRACE=1 open -n --env TINYSTATS_CLICK_TRACE=1 build/TinyStats.app
```

`open --env` explicitly forwards the variable through LaunchServices. Only the exact value `1` enables tracing for that process; ordinary launches are off. There is no preference key or UI. One line per relevant mouse event records its type, source window class/number/frame, `locationInWindow`, current screen mouse position, the cross-checked own-status-window screen point, each visible status-button screen rectangle (or unavailable), and the routed module/transition or pass-through reason. Output goes to unified logging under the subsystem/category above, with public coordinate fields for this explicit diagnostic session; TinyStats writes no trace file, keeps no event history and adds no monitors or permissions. Quit and relaunch normally to stop tracing. Review log excerpts before sharing them.

With physical mouse clicks, check both Separate and One: open CPU; click Memory once and confirm the same dropdown switches; click Memory again to close; quickly click another module during closing and confirm it opens. In One, check every icon/value segment and gaps. Click dropdown controls and unrelated TinyStats windows to confirm they receive their clicks. Repeat on each attached display and with menu-bar auto-hide/available notch space; hidden items must not route. Check right-click options, unchanged Control-click opening, ⌘-drag, and keyboard/VoiceOver activation of the first module. Compare logged screen points/rectangles and transitions with the visible result. These are manual maintainer checks: tests never post real menu-bar clicks, move the pointer or enable this trace implicitly.

## Drag customization and accessible actions

The grouped customization platter contains rounded SF Symbol/name chips. Both wells wrap with 8-point gaps and grow in height, pushing the following controls down. Drag from **Available** into **In menu bar** to enable a readout at the accent insertion marker. Drag within the strip to reorder; drag onto **Available** to remove. Dragging outside either destination, or cancelling with Escape, leaves settings unchanged. At least one readout must remain. An unavailable hardware reading still has a chip; enabling a Weather readout does not authorize Weather requests.

Right-click a chip for **Add to menu bar**, or **Remove from menu bar**, **Move left/right**, **Move to start/end**. Inapplicable actions are disabled. Tab/Shift-Tab focus the chips; plain Left/Right focuses the adjacent chip. Return/Space adds or removes, and Option or Command + Left/Right moves one position; add Shift to move to the start/end. VoiceOver exposes the labeled In menu bar and Available groups and named custom actions, announcing the new position or removal. VoiceOver press selects the chip’s style editor without changing membership; the selected chip’s value includes “Editing styles”. Keyboard focus stays with the moved chip and selects its editor without expanding a collapsed section. The picture tiles and font-size popup edit the selected module, with sensor/format controls scoped to that module’s header; disabled readouts retain their styles. Layout changes preserve the enabled set, order and styles and refresh the preview immediately.

Readout membership and order persist through the existing `settings` JSON `readouts` array. The saved `separateItems` choice selects Separate/One independently of per-module styles and sizes. The obsolete `menuBarSpacing` key is ignored on decode, including unknown or malformed values, and omitted on encode; legacy profiles therefore migrate to compact geometry without changing other choices. Returning from One to Separate reuses saved native module positions. Legacy arrays retain their recognized enabled items and order. Unknown/duplicate/Overview entries are discarded individually; an explicitly empty or malformed selection falls back to CPU only, preserving access without enabling extra default items. Missing lists keep the original CPU/Memory/Network default. Explicit Weather/History choices and unrelated settings are preserved.

For older profiles and later native ⌘-drags, the existing main-actor refresh adopts only a complete, distinct, onscreen native order into `readouts`. Partial/overflow frames cannot replace the saved layout. Adoption is blocked throughout rebuilding and after explicit edits until the requested order is observed or a complete differing order stays identical across two consecutive existing refreshes. Incomplete frames break that stability check. Failed placement clears pending enforcement and lets the preview show the observed order, but the stable mismatch is a baseline rather than a settings edit: saved intent remains authoritative for later enforcement. Subsequent changed native orders can be adopted as ⌘-drags. Explicit Settings edits rebuild native items and remap TinyStats' position slots through AppKit's `NSStatusItem Preferred Position <autosaveName>` defaults convention. Only saved autosave values supply slots; live button-center distances are never mixed into them. Surviving slots are retained during simultaneous removal/addition, with new insertion anchors between or beside them. AppKit exposes autosave names but no public item-moving method; that placement convention remains an OS-dependent integration point. Other apps' keys are untouched. Isolated preview launches use isolated autosave names. Native reorder behavior on other macOS versions/displays still requires runtime validation.

Reorders use a short AppKit frame animation, respecting Reduce Motion; the chip drag image is rendered from the chip itself. Nine reused chips, one private local pasteboard type and source-instance validation bound the UI state. No external drops, data collection, new timers, polling, network requests or permissions are added. The existing `TINYSTATS_SYSTEM_RENDER_PATH` gallery includes whole-pane light/dark images and customization crops.

## Battery values and power-state presets

Select the **Power** chip and use **Battery formats…** in its style header (or compact row on a narrow pane) to open **Battery Menu Bar Format**. The default value format follows the main row's style. **Use different displays for each power state** enables four independent value/style presets: On battery, Charging, Charged and On AC · not charging. The main Power style is disabled while presets are enabled; font size remains shared and colors are automatic. Text values apply to Label + value, Stacked, Value only and History + value. Other styles disable the value-format control and keep battery-percentage semantics, including horizontal gauge captions.

The editor reuses the production renderer at native height and menu bar appearance. Choose **Live reading** or a clearly labeled **Example** to inspect a different state. Examples change only that preview; they never enable the Battery item, replace collected readings, add fake history or write state into settings. The main Menu Bar preview always uses live data. See [battery formats](BATTERY.md) for estimates, charge-hold handling and limits.

## Data, persistence and resource limits

Settings builds each tab on first visit and retains visited pages until the window closes. Switching tabs preserves unsaved world-clock text. The hidden or minimized Menu Bar host skips preview updates, including clock/context changes, and catches up with current readings and native bar appearance when shown again, using the same shared sampler. Closing detaches the embedded page tree.

Missing readings display as an em dash or an unavailable graph/gauge state. Missing history samples break a line; a valid zero remains zero, including an empty zero-level gauge. Icon/label-only styles deliberately omit the number. Battery AC is the no-internal-battery state rather than a fabricated charge percentage.

Both graph families use the last 40 points from the existing bounded history. When a visible readout uses History graph or History + value, history is delivered even with details closed. Graphs add no timer or sampling request. Rendering reuses bounded shared font/symbol caches and draws directly into native status buttons, without an animation loop.

Existing raw style and size choices remain. Saved `separateItems: false` restores One; missing or malformed layout values default to Separate. Former preset users retain their saved module styles and sizes, with their existing Separate layout. Missing appearance settings default to Standard/Automatic; malformed appearance entries fall back per module without erasing unrelated choices. Unsupported persisted style/metric combinations use the stacked fallback. Changing sensor quantity limits its styles to meaningful options rather than inventing a fan/power percentage.

## Research and remaining scope

[Bjango's official feature overview](https://bjango.com/mac/istatmenus/) is the competitive feature reference. A separate read-only UI inventory of **iStat Menus 7.30** observed vertical, pie, ring and labeled-horizontal gauges, along with value, stacked, icon, label, history and per-core presentations. These are visible UI observations, not claims about its implementation. TinyStats' renderer is independent; no proprietary code or assets were copied.

This milestone supplies these native style families for TinyStats' existing readings. It does not reproduce every commercial preset or metric combination. Custom one/two-line clocks, inline analogue dials, mini calendars, fuzzy time and Mac-relative offsets are documented in [clock formats](CLOCKS.md). Deterministic [rendering fixtures](../Tests/TinyStatsUITests/MenuBarRenderingTests.swift) generate a local gallery with the production renderer.

Weather offers the five text/icon families and uses its opt-in forecast temperature or condition symbol. It has no percentage gauge or fast-sampler history. Configure the provider/location on the Weather monitoring tab; see [Weather](WEATHER.md).
