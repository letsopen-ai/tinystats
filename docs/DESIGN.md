# TinyStats design

2026-10-22 · main · niechen/tinystats · Builder mode

## Problem
Keep a Mac's core system information within one click without the monitor itself becoming a meaningful source of CPU work, memory use, disk writes, or network traffic. Target: developers and power users who want iStat Menus-style local visibility and an inspectable, small native app.

## Premises
- A lightweight alternative needs measurements, not an unverified claim of being lighter than iStat Menus.
- CPU, GPU, memory, storage, network, thermal/power sensors, battery and date/time are the local core. Weather, calendar integrations, custom fan curves and complete app-level network aggregation need separate capability and cost decisions. The partial kernel TCP/UDP process view requires no elevated privileges.
- Missing hardware data must be presented honestly, never replaced with invented numbers.
- Signed binary releases wait until the release checklist in [Distribution](DISTRIBUTION.md) is satisfied.

## Alternatives
A. Minimal AppKit monitor: native popover, one sampler, no packages. Small effort; low runtime overhead, but hardware adapters need care. Selected.
B. SwiftUI menu bar app: fast declarative layout; larger view graph and less control over redraws. Medium effort; benchmark before considering.
C. Fork Stats (MIT): broad existing compatibility, but imports a large feature surface and architecture; harder to substantiate a small resource budget. Large audit effort. Use as protocol research, not a fork.

## Architecture
Swift 6, macOS 14+, Swift Package Manager. A small C boundary for kernel/IOKit/libproc interfaces; pure Swift data models, rate calculation and bounded ring buffers; AppKit UI. One serial utility queue owns the sampler. One coalesced dispatch timer, two seconds by default, slower in Low Power Mode. No overlapping sampling. Sleep stops sampling; wake resets cumulative baselines. Process sampling runs only with details visible, in the popover or development preview window. Hardware discovery and storage capacity refresh run slowly. No subprocesses in the sampling loop. No third-party runtime dependencies, telemetry, or unauthorized network requests. Weather is off by default for new installs; enabling it is an explicit opt-in. TinyStats’ own macOS location permission additionally gates current-location coordinates and forecasts. Existing explicit choices remain unchanged.

Use elapsed monotonic time for rates. Treat first samples, resets, interface replacement and wake as fresh baselines. Retain at most 300 recent raw samples plus 1806 numeric history buckets across six bounded history tiers. Checkpoints default On for new/missing preferences, preserve explicit Off and reject malformed explicit values to Off; they retain those buckets across launches, with a maximum 8,621,920-byte v3 file when per-core data is retained (scalar-only v2 is capped at 758,596 bytes; v1 reads remain supported) and five-minute dirty-save cadence on the existing serial worker; enable and best-effort sleep/Quit can also save. Off preserves the checkpoint and Clear confirms removal; see [History](HISTORY.md) for privacy, merge and failure semantics. Read network counters per interface and count only the selected interface, preserving separate tunnel and physical totals. Distinguish physical disk I/O from mounted-volume capacity. Process IDs include start time to avoid reuse spikes.

The 0.4.0 Apple Silicon adapter dynamically resolves the optional IOReport interface through an original C boundary. One subscription selects at most 32 relevant channels, with at most 64 states per channel, and shares the existing >=5-second hardware cadence. Active CPU-cluster/GPU frequency is weighted by residency deltas and excludes idle/off time. Recognized energy channels provide separate model-power estimates in watts; overlapping rails are not summed into whole-system power. First/reset samples, unknown units/layouts and state/table mismatches stay unavailable. Energy must actually increment before a zero-watt interval is accepted. Pause/sleep resets the subscription and baselines; no fan write, administrator privilege, subprocess or timer is added.

The 0.5.0 network adapter separates traffic counters from cached local metadata. SystemConfiguration callbacks only set an atomic invalidation flag on the existing sampler queue. The next shared tick refreshes after a notification or interface identity/flag change; a 30-second fallback covers missed notifications. Discovery retains at most 128 interfaces and eight addresses per interface, preserving IPv6 scope/prefix/state and explicit truncation. A failed read clears its cached data; a successful empty result remains distinct. Name/index checks prevent addresses from following a replacement interface and restart pending network-rule holds. Auto prefers an existing/up IPv4 primary interface, then IPv6, and counts one interface across protocols without destination-specific route lookup. No probe, subprocess, timer or network-setting write is added.

The 0.7.0 process-traffic adapter independently implements public kernel TCP/UDP accounting. It opens only for visible Network details and shares the serial sampler queue, using one dispatch read source without an additional timer. Pausing, sleeping, hiding details or switching modules cancels collection and clears baselines. Draining yields after 32 datagrams or about 2 ms; retained state is bounded to 8,192 socket sources and 1,024 PID + kernel-unique-ID owners, with top-eight output, a requested 256 KiB kernel receive buffer and 64 KiB scratch buffer. Endpoint fields are never decoded, logged or retained; the raw scratch buffer is cleared immediately after decoding, even on failure.

Two complete queries establish initial rates. Unknown layouts, missing updates, capacity/byte overflow, identity changes and counter resets invalidate the interval rather than producing partial totals or false zeroes. Recovery establishes fresh baselines; missing updates trigger an inventory reopen after five seconds and hard failures retry after 60 seconds on the shared cadence. Closed-socket final counters retain traffic from sockets born entirely between polls while birth timestamps exclude pre-baseline cumulative bytes.

The 0.27.0 Network selector, now shared with CPU/Memory as the section-header Processes / Apps control, retains Processes as the default and optionally groups complete owner rates by current outermost executable bundle path before ranking. Only this worker-local projection expands to the existing 1,024-owner bound; eight process rows/groups reach display and the graphical summary fits up to eight as height allows. Guarded worker kernel identity/path calls use no filesystem metadata or AppKit; only displayed bundle rows request bounded main-actor names/icons and path tooltips; unchanged ready snapshots reuse the bounded display projection. Mode changes rebaseline and advance a persisted revision to reject stale/ABA deliveries. Active member counts exclude idle owners, unresolved/shared brokers stay separate, and current executable paths do not establish delegated responsibility or complete modern/QUIC coverage. See [Network](NETWORK.md) and path provenance.

History 0.28.0 adds bounded per-metric minima, sample means and valid counts alongside existing peaks. One packed aggregate array per populated bucket uses the known twelve-metric capacity; legacy-only aggregates stay unavailable. Headlines and compressed columns combine means by valid observation counts, including repeated cached readings; these are not time averages or independent hardware-read counts. CPU peak components remain paired, while component minima/means are independent CSV values. No collection cadence or timer changes. The maximum populated-archive experiment adds577920B of live heap allocation, distinct from RSS/footprint and whole-app budgets. V2 retains the historical checkpoint path; downgrade and Off-retains semantics are documented in [History](HISTORY.md), with allocation/resource limits.

The detail controller also owns a separate `SensorTimeline` since 0.35.0: up to 132 identities × 120 Float readings (63,360 bytes of numeric payload plus containers and a shared time axis), appended only for new existing ≥5-second hardware observations. Its lifetime follows the detail view, including tab switches, and closing releases it. Search/selection and fitted unit-bearing charts do not change the selected-menu-sensor checkpoint archive or add collection, timers, network or disk writes.

Scalar summary, mini and recorded-history plots prepare immutable dates, domain and derived `HistoryTimeline` together since 0.33.3. Replacing the whole axis prevents stale positions/gaps; width/statistic aggregation remains dynamic. Input intervals are not retained after derivation, but positions/gaps are bounded state for the plot lifetime. The core matrix keeps its independently derived cadence/gap inputs. This reduces measured repeated component work with a +64B inline Plot tradeoff, not established whole-app memory savings; see evidence.

The drop wells and outer customization group are neutral, so no full glass layer sits beneath another.

The panel's material content draws a semantic window-background wash at **60% light / 70% dark**. This follows Apple's [AppKit design guidance](https://developer.apple.com/videos/play/wwdc2025/310/) and [Liquid Glass adoption guidance](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass): glass belongs to functional/navigation surfaces; neighbouring shapes share a container. Offscreen gallery PNGs prove layout/ink only. The explicit ScreenCaptureKit fixture preflights existing permission, captures only its own synthetic window over saturated colour stripes and a smooth multi-hue gradient, and separately exercises full-content Reduce Transparency/Increase Contrast policy inputs without changing OS preferences or requesting access.

## Verification and success criteria
- Unit tests cover rate resets/wraps, history bounds, CPU normalization, pressure, rules and persisted settings validation.
- Release build and app bundle must run on the development Mac (Apple M4). Cross-compile Intel and build a universal binary.
- Diagnostics exercise real collectors and distinguish unavailable capabilities from valid zero values.
- Measure steady-state closed-popover CPU, RSS, sampler duration and app size; record actual measurements and methods. Initial engineering targets: <1% of one CPU core at 2s cadence; <40 MiB resident memory; <10 MiB universal app. These are targets until verified.
- Test opening/closing details, settings persistence, status layout, pause/resume and sleep baseline logic.
- Hardware telemetry must fail gracefully without elevated permissions. No fan writes in the initial build; release matrix must state this limitation.

## Distribution
Reproducible scripts create a universal .app and ZIP. Local execution covers its actual host only. Public releases still require Developer ID signing/notarization and a hardware validation matrix. Contributions use feature branches and pull requests; see [Contributing](../CONTRIBUTING.md). Preparing source for open-source participation does not complete signed binary distribution gates.

| --- | --- | --- | --- |
| CPU | total and per logical core %, 1/5/15min load, uptime, top apps | Mach ticks / selected cadence; processes only in open details | — and explanation |
| GPU | model, driver utilization %, allocated memory if exposed | IOAccelerator registry / selected cadence, discover every 60s | explicit unsupported-driver message |
| Memory | working set, active/wired/compressed, reclaimable categories, pressure, swap, top apps | host_statistics64 + sysctl / selected cadence | — |
| Disks | local mounted capacity, physical read/write rates, top app I/O | getmntinfo every 30s; IOBlockStorageDriver each sample | no false zero on missing driver |
| Network | selected interface rates, counters, local IPv4, interface list | 64-bit routing counters each sample; default route every 30s | disconnected/unavailable |
| Sensors | readable temperatures, RPM, watts, volts, amps; OS thermal state | AppleSMC read-only every >=5s | no helper prompt; no fabricated data |
| Battery | charge, charging state, time estimate, health, cycles, power; HID peripheral charge | IOPS + registry every >=5s; HID every 30s | desktop/no battery state |
| Time | local date/month calendar, up to six editable world clocks | system date/time on shared cadence | invalid zone rejected |

CPU total is 0–100% of machine capacity; per-process CPU is 0–100% per logical core and may exceed 100%. The current memory composition bounds wired to total, physical compressed allocation to the remaining total, and estimated app (active less purgeable) to the remainder; available is the final remainder including cache/free. These are non-overlapping estimates, not exact process accounting; raw overlapping categories remain in All readings. Pressure is the kernel’s categorical state, not a percentage heuristic. GPU utilization uses the driver's counter, and does not imply kernel task attribution or GPU frequency. Physical disk rates are summed once per registry driver identity; volume free space is reported individually because APFS volumes can share capacity. Auto network follows the primary IPv4 route; manual selection supports VPN interfaces without aggregate double-counting.

Settings: 1/2/5/10s cadence, combined/individual items, ordered module readouts, manual/auto interface, Celsius/Fahrenheit, six world clock IDs, login and alert opt-in. All modules remain accessible through the popover. macOS may hide extra status items on notched/constrained displays; the combined default and settings afford recovery. Pause stops the shared timer and marks readings paused; resume and wake clear baselines. Low Power Mode has a minimum 5s cadence. Time/calendar remain local; account events and weather do not ship in v0.1.

Alerts are off by default. If enabled: CPU >=90% for 30s, critical memory pressure for 10s, a volume >=95% full for 10s, battery <=20% while draining. Per-rule 15min cooldown. Sleep/resume resets sustained-condition timers. No custom rule editor in v0.1.

Performance procedure: Release build on Apple M4, 15s warm-up, >=60s steady closed-popover sampling at 2s, record process CPU-time delta divided by monotonic elapsed time (one core), RSS/footprint endpoints and sampler duration distribution. Repeat with details open. Record environmental load; no comparison claim versus competitors without a matched experiment. Missing targets block public readiness, not truthful private delivery. Intel cross-compile is required here; Intel runtime validation remains a public-release gate.

Independent design review: first pass 7/10. Clarified per-module contract, semantics, rules/pause, settings bounds, measurement methodology and release gates.

Alert delivery uses local macOS notifications after explicit opt-in and permission. A condition that remains true may notify again after the 15-minute cooldown; recovery resets the hold timer. The original CPU/memory/disk per-process readings use libproc on the selected cadence only while details are open. The 0.7.0 process-traffic view uses the kernel stream described above only while Network details are selected. No process samples are taken by the closed-popover worker.

Final design review: 8.5/10; no blocking findings. The two remaining clarifications (libproc cadence and alert delivery/rearming) are specified above.

## Calendar agenda (0.8.0)

Account events are an explicit opt-in with a separate permission action and calendar chooser. The native month grid now provides selectable day buttons with accessibility labels and standard keyboard focus. Queries use one local civil-day interval, with midnight/DST boundaries and pinned-day time-zone behavior tested. The agenda precedes world clocks, labels all-day events, and marks partial results rather than implying complete store coverage.

One lazy EventKit store lives on a dedicated utility queue. Existing sampler deliveries drive a 60-second fallback and coalesced store-change invalidation; no additional timer or overlapping job is added. Generation checks discard stale work. Retention is bounded to 64 calendars and 128 event rows, with enumeration stopped after 2,048 candidates. Closing/leaving, disabling, pause and sleep clear agenda values; the chooser can retain metadata while visible. Date & Time skips unused process scans.
