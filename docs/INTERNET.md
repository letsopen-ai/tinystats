# Optional advanced internet checks

Settings → General → **Online & Time advanced** → **Internet checks…** has three independent opt-ins. The advanced section starts collapsed each Settings session. These are optional advanced features; the welcome tour keeps Weather primary and offers Internet checks as a secondary advanced setup action. Opening the section or setup does not enable requests. All default to off; migration preserves existing explicit choices. Select the options and press **Save** to authorize scheduled requests while details are closed. Edits and toggles are a draft until Save; Cancel or closing discards them. The window names each destination, cadence and public-IP disclosure before the switches. Turning on alert notifications does not enable these requests.

| Option | Request | Normal cadence | Meaning |
| --- | --- | --- | --- |
| Apple HTTPS response | GET `https://www.apple.com/library/test/success.html` | 60 seconds | Expected HTTP 200 and the known success page; full check response time |
| Custom HTTPS response | GET the explicitly saved HTTPS URL | 60 seconds | One chosen HTTP status in 200–299; status only, no body-content verification |
| Public IPv4 | GET `https://api.ipify.org` | 5 minutes | Provider-reported IPv4 egress address |
| Public IPv6 | GET `https://api6.ipify.org` | 5 minutes | Provider-reported IPv6 egress address, if available |
| ICMP ping | Echo to one explicitly saved numeric IPv4/IPv6 address | 30 seconds | Endpoint round-trip time; five-second reply window |

The selected HTTPS server and ipify see the connection's public source address and ordinary request metadata. TinyStats sends no device identifier, local interface address, metric history or account/event data. It uses an ephemeral session, no cookies, URL cache or credential storage, and never supplies account/proxy credentials. System TLS validation stays enabled. Redirects are rejected, including to another path on the same host. No provider geolocation API is called. TinyStats retains results in memory only; it does not save returned addresses in preferences, logs, diagnostics or history.

HTTPS and public-IP requests follow the OS-selected route, proxy and VPN. They are independent of the interface selected for the link-byte headline. ICMP routing and proxy bypass are described below. A failed HTTPS request does not prove that the entire internet is offline, and an expected response does not prove that all other services work. The timing includes client setup, DNS/TLS/HTTP and response completion; it is not ICMP ping. IPv6 can be unavailable without making IPv4 unavailable. Syntactically validated addresses describe the provider response, rather than proving routability or the absence of a proxy.

## Network panel and rules

Network details show endpoint state, a short result reason, successful HTTPS check time, provider-reported addresses and ages. Disabled checks are explicitly off; failures clear old values. Right-click a value to copy it. An IP address is not automatically copied or included in a notification.

The rule editor adds **HTTPS response state**, **HTTPS response time** and **Observed public-IP change**. State choices distinguish request failure, expected response and unexpected response. Response-time thresholds use milliseconds and require a successful expected response. HTTPS observations expire after 90 seconds; IP observations expire after 330 seconds. Missing/stale/disabled observations do not trigger rules.

A public-IP rule selects IPv4 or IPv6. The first successful response establishes a baseline and never triggers a change. A later different successful response creates one observed change, including across a route change or failed intervening requests. This does not establish when the underlying address changed between polls. Changes have zero duration and at most one notification per observation, subject to cooldown; each new observation rearms independently. Unchanged replies clear the change condition. Pause/sleep, disabling public-IP checks or changing opt-ins clears the baseline.

Opt-in revisions and request tokens reject late results, queued pre-opt-out/pre-pause snapshots, duplicate completions and queued alerts after disable/re-enable. Alert delivery rechecks current notification settings, the matching rule, the specific internet opt-in and its revision. No actual OS banner/sound permission was changed for tests.

## Resource and lifecycle contract

The shared sampler drives scheduling and a fallback deadline check. No extra sampler/polling timer or subprocess is added. For HTTPS/public-IP checks, a lazy native URLSession has at most one logical request active. Normal request and whole-resource timeouts are eight and ten seconds; the shared tick also abandons an unfinished logical request after twelve seconds. Framework cancellation may finish asynchronously, and internal URLSession allocation/chunks are outside TinyStats' application-buffer bounds.

Application-owned response bodies are capped at 1,024 bytes for Apple/custom HTTPS checks and 128 bytes per IP family. Oversized responses fail rather than accumulating more data. HTTP delegates run serially, with a short lock protecting state shared with the sampler; no blocking network wait occurs on the sampler/UI. Completed raw bodies are released after typed decoding.

A bounded interface/address/route/DNS fingerprint invalidates results after a local path change. Refreshes can then occur sooner, with a ten-second minimum per endpoint and oldest-request-first scheduling to avoid starvation. This fingerprint is not a complete destination-specific routing or proxy-configuration monitor. Without an observed change, the normal 60/300-second cadence still refreshes results. The fingerprint is not built at all when checks are off.

Pause/sleep and opt-out cancel current work. Disabling both HTTPS and public-IP choices invalidates/releases their session; independently enabled ICMP uses the separate native socket described below. Resume starts fresh baselines; request rate limits survive pause/disable so toggling cannot create a request storm. Results and queued notifications from an earlier opt-in/lifecycle revision are discarded. Closing details alone leaves explicitly enabled checks active, as disclosed in Settings.

## Reproduction and evidence

Normal tests intercept native requests with URLProtocol or inject a transport and make no external requests. The explicitly enabled `TINYSTATS_VALIDATE_INTERNET=1 swift test --build-system native` fixture sends one request to each named endpoint, checking Apple's content and public IPv4 parsing; IPv6 availability is not assumed. It logs only status/category/byte count, never an address. A live run exercised Apple's expected reply and ipify IPv4 successfully. A provider URL canonicalization regression was found and fixed: URLSession may add a root slash to a bare origin, which the allowlist now normalizes without allowing a different scheme/host/path.

For a real app workload, `python3 scripts/benchmark-app.py --preview --module network --internet-checks --warmup 15 --duration 60` explicitly enables the same endpoints in the harness-owned preferences. This command makes external requests; ordinary benchmark invocations do not. It records resource metadata rather than returned addresses.

Sources: [Apple's success page](https://www.apple.com/library/test/success.html), [ipify's official API documentation](https://www.ipify.org/), and Apple's [URLSession data delegate](https://developer.apple.com/documentation/foundation/urlsessiondatadelegate), [connectivity waiting](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/waitsforconnectivity), and authentication documentation/SDK interfaces. No proprietary code is used.

Remaining work includes hostname-based ping, live external/LAN/scoped-IPv6 validation, explicit proxy/network-change runtime fixtures, live external IPv6 success, representative hardware/sleep/VPN validation and actual OS notification delivery. This feature does not establish full iStat Menus network parity.

## Configurable HTTPS destination (0.26.0)

The Apple preset still checks its exact success-page content. Choose **Custom HTTPS endpoint · status verified** to enter one HTTPS URL and an expected successful status from 200 through 299 (for example HTTP 204 for a small health endpoint). The preview shows the exact request and expected-response meaning separately. Long request previews truncate in the middle with the complete URL in the editable field and tooltip. Save applies destination, status and opt-ins atomically; existing settings migrate to the Apple preset. A malformed saved custom configuration disables HTTPS checks rather than silently requesting Apple. Public-IP enablement is independent.

Custom checks verify the configured status, not page content or general internet connectivity. A wrong status, redirect, TLS/DNS failure or body larger than 1,024 bytes withholds successful latency. Use a small health endpoint; an ordinary large page may exceed the limit. Only port 443 is supported. URLs are limited to 512 ASCII bytes and cannot contain a username, password, query or fragment; do not put secrets in a path. The configured URL/status are saved locally in preferences. Returned bodies and results remain memory-only. The displayed destination follows the OS route and may refer to an explicitly entered private/local service. TinyStats does not scan or discover endpoints.

HTTPS alert rules now follow the configured endpoint, including existing Apple rules. Changing URL, status or opt-ins cancels old work, clears old results and starts a new alert hold; queued results and alerts must match both the current opt-in revision and destination configuration. The same shared scheduler, 60-second normal cadence, 10-second invalidation floor, one in-flight request, timeouts and no-credential/no-redirect policy apply. Public-IP source/meaning is unchanged. No custom endpoint is enabled on install or by diagnostics/tests. Tests use injected transports and URLProtocol interception, not external custom requests.

Saving an unchanged draft preserves the existing revision, results and public-IP baseline. A real endpoint/opt-in change currently resets the shared internet-check revision, including the public-IP baseline; request rate floors remain in effect. HTTPS alert text remains generic; use a named rule to identify its purpose. Before running a pre-0.26 build, disable HTTPS checks: those builds ignore custom destinations and use Apple. Dot and dot-dot URL path segments are rejected so URL normalization cannot silently change the observed destination.

Native evidence separates the earlier binary's invalid/Cancel checks from final-binary Light/Dark disclosure and unchanged-Save checks. Both request types stayed off; no custom server was contacted.

## ICMP ping (0.32.0)

General → **Online & Time advanced** → **Internet checks…** → **Enable ICMP ping** measures round-trip time to one IP address you choose. There is no default destination. Enter a numeric unicast IPv4 or IPv6 address and Save; hostnames are not resolved. Cancel or closing discards the draft. Existing HTTPS and public-IP choices are independent. Enablement scrolls the destination and complete ICMP/privacy disclosure into view; the resizable window keeps Save/Cancel visible.

One 24-byte echo is normally sent every30 seconds, including with details closed. The five-second reply window excludes DNS, TLS and HTTP; the receive callback measures monotonic elapsed time since send. The OS route/VPN applies, and HTTP proxies are bypassed. Scoped link-local IPv6 explicitly uses its named interface, such as `fe80::1%en0`, instead of the link-byte interface selection. Interface names are saved and resolved when sending; a temporarily absent VPN/dock reports **IPv6 interface unavailable** without erasing the saved opt-in. Numeric scope indexes are rejected because they can change across boots.

The destination sees the packet's source IP. LAN requests may prompt for macOS Local Network access only after you enable/save a destination; TinyStats does not scan or discover hosts. A restricted socket operation reports **Network access restricted** with permission/firewall guidance; errno alone cannot identify which protection denied it. No permission was granted during validation. IPv4/IPv6 loopback is the only live test target so far; actual LAN permission transitions, scoped IPv6, VPN and external ICMP remain unverified.

Network Summary shows the chosen destination, RTT or neutral failure/unavailable reason and result age. All readings includes the complete result and route meaning. **No echo reply** is not evidence that the Mac or entire internet is offline. Hosts may ignore ICMP. Missing, stale-generation and failed readings never become zero latency. Results are memory-only and are not added to numeric history, CSV, diagnostics, alerts or menu-bar items. The selected destination/opt-in are saved locally in preferences.

Ping uses an unprivileged nonblocking datagram socket, one pending echo and one read event source, with no subprocess or new polling timer. The shared sampler drives scheduling, path invalidation and timeout cancellation. Replies older than five seconds are rejected; a silent socket is closed at the next shared sample (nominally up to10 seconds with the supported cadence, plus dispatch delay). Pause, sleep, Off, route/configuration changes and teardown cancel pending work and reject late replies. A10-second floor survives toggles/reset/route storms. HTTP still has at most one active logical request; one ping can run alongside it.

Receive storage is capped at 1 KiB, work at 16 datagrams per callback/64 per request. Replies must match family, sender, identifier, sequence and a fresh128-bit opaque payload. IPv4 header/options/length/fragment/protocol and ICMP checksum are validated; IPv6 checksum validation is supplied by the kernel. Unspecified, multicast, limited-broadcast and mapped IPv6 destinations are rejected; broadcast sending is never enabled on the socket. File descriptors close in the read source's cancellation handler. A small lazy ledger/transport object remains after use to preserve request floors; this is not a zero-allocation claim.

Default-off diagnostics do not open a ping socket or enable requests. Ordinary tests inject transports; `TINYSTATS_VALIDATE_ICMP_LOOPBACK=1 swift test --build-system native` additionally sends localhost-only IPv4/IPv6 echoes. The app currently has no App Sandbox entitlement; no helper, root privilege or entitlement expansion is added. Sources: Apple's [SimplePing](https://developer.apple.com/library/archive/samplecode/SimplePing/Introduction/Intro.html), [Darwin ping source](https://github.com/apple-oss-distributions/network_cmds/blob/main/ping.tproj/ping.c), local Darwin `ip(4)`/SDK headers and [Local Network usage description](https://developer.apple.com/documentation/bundleresources/information-property-list/nslocalnetworkusagedescription). The implementation is independent, with no copied proprietary code or third-party runtime dependency.

0.32.0 cancellation also invalidates queued, not-yet-sent ICMP work synchronously; the final nonblocking send is atomic with that admission check. Disabling hides the summary row even when an invalid draft address is retained locally. Ping-only operation reports “Network checks enabled” in About this sample and Pause/Resume tooltip/VoiceOver help; dropdown footers contain only icons.
